# 브랜치 전략: 웹 · iOS · 앱인토스 (#301, #303)

머핀은 **코드 하나**로 웹, iOS 앱, 앱인토스를 함께 운영합니다.
출시 대상인 **iOS 앱 작업은 `ios` 브랜치**에서, 웹·공통 작업은 `dev`에서 진행하고 두 브랜치를 자주 맞춥니다.

```
feat/* · fix/* (iOS 앱 작업) ──▶ ios ──(필요할 때)──▶ dev
feat/* · fix/* (웹·공통 작업) ──▶ dev ──(주기적으로)──▶ ios
                                    └──────────────▶ toss
```

## 브랜치

| 브랜치 | 용도              | 들어오는 것                              | 배포                                   |
| ------ | ----------------- | ---------------------------------------- | -------------------------------------- |
| `ios`  | iOS 앱 개발·배포  | iOS 앱 작업 PR, `dev` → `ios` 동기화 PR  | Codemagic `ios-testflight` (수동 실행) |
| `dev`  | 웹·공통 기능 개발 | 웹·공통 작업 PR, `ios` → `dev` 동기화 PR | Vercel (push 시 자동)                  |
| `toss` | 앱인토스 배포     | `dev` → `toss` PR만                      | 앱인토스 연동 후 정리 예정             |
| `main` | 기존 배포 브랜치  | 기존 방식 유지                           | -                                      |

## 규칙

1. **iOS 앱으로 출시할 작업은 `ios`로 PR**을 올립니다. 작업 브랜치도 `ios`에서 따옵니다.
   ```bash
   git fetch origin ios
   git checkout -b feat/123-native-login origin/ios
   ```
2. **웹·공통 작업은 기존처럼 `dev`로 PR**을 올립니다.
3. **두 브랜치를 자주 맞춥니다.** 오래 떨어져 있을수록 합칠 때 충돌이 커집니다.
   - `dev` → `ios`: `dev`에 머지된 게 있으면 바로 (적어도 주 1회)
   - `ios` → `dev`: 웹에도 필요한 작업이 `ios`에 머지되면 바로
   - 동기화는 일반 머지 PR로 합니다. rebase·force push는 하지 않습니다.
4. **플랫폼마다 다른 코드는 코드 안에서 나눕니다.** `ios`에 있는 코드가 `dev`로 넘어가도 웹이 깨지지 않게 합니다.
   - iOS 앱인지: `Capacitor.isNativePlatform()` (`@capacitor/core`)
   - 앱인토스 전용 처리: 앱인토스 연동 시 실행 환경 확인 방법을 정해 이 문서에 추가
5. `toss`는 배포 전용입니다. `dev` → `toss` PR만 받습니다.

## 언제 어느 브랜치로 PR을 올리나

| 하고 싶은 것                                                | PR                                       |
| ----------------------------------------------------------- | ---------------------------------------- |
| iOS 앱 기능·버그 수정 (네이티브 로그인, 푸시, Safe Area 등) | `feat/…`·`fix/…` → `ios`                 |
| 웹·공통 기능 (다른 팀원 작업 포함)                          | `feat/…`·`fix/…` → `dev`                 |
| `dev` 변경을 iOS 앱에 반영                                  | `dev` → `ios`                            |
| `ios` 변경을 웹에 반영                                      | `ios` → `dev`                            |
| iOS 앱 새 빌드 (TestFlight)                                 | Codemagic에서 `ios` 브랜치로 Start build |
| 앱인토스 배포                                               | `dev` → `toss`                           |
