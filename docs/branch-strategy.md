# 브랜치 전략: 웹 · iOS · 앱인토스 (#301)

머핀은 **코드 하나**로 웹, iOS 앱, 앱인토스를 함께 운영합니다.
기능은 전부 `dev`에서 개발하고, 플랫폼별 브랜치는 **배포용**으로만 씁니다.

```
feat/* · fix/* ──▶ dev    웹 (Vercel 자동 배포)
                     │
                     ├──▶ ios    iOS 앱 (Codemagic → TestFlight / App Store)
                     └──▶ toss   앱인토스
```

## 브랜치

| 브랜치 | 용도                | 들어오는 것                               | 배포                                      |
| ------ | ------------------- | ----------------------------------------- | ----------------------------------------- |
| `dev`  | 모든 기능 개발·통합 | `feat/*`, `fix/*`, `chore/*`, `docs/*` PR | Vercel (push 시 자동)                     |
| `ios`  | iOS 앱 배포         | `dev` → `ios` PR만                        | Codemagic `ios-testflight` (push 시 자동) |
| `toss` | 앱인토스 배포       | `dev` → `toss` PR만                       | 앱인토스 연동 후 정리 예정                |
| `main` | 기존 배포 브랜치    | 기존 방식 유지                            | -                                         |

## 규칙

1. **기능 커밋은 `dev`에만** 합니다. `ios`·`toss`에 직접 커밋하거나 기능 PR을 올리지 않습니다.
   - 배포 브랜치에 직접 고치면 `dev`와 내용이 달라져서 다음 배포 때 충돌이 납니다.
2. **플랫폼마다 다른 코드도 `dev`에 둡니다.** 브랜치로 나누지 않고 코드 안에서 실행 환경을 확인해 나눕니다.
   - iOS 앱인지: `Capacitor.isNativePlatform()` (`@capacitor/core`)
   - 앱인토스 전용 처리: 앱인토스 연동 시 실행 환경 확인 방법을 정해 이 문서에 추가
   - 네이티브 프로젝트(`ios/`), 빌드 설정(`capacitor.config.ts`, `codemagic.yaml`)도 `dev`에 있습니다.
3. **배포는 `dev` → 배포 브랜치 PR을 머지**해서 합니다.
   - 예: iOS 새 빌드를 올리려면 `dev` → `ios` PR을 만들고 머지 → Codemagic이 자동으로 빌드해 TestFlight에 업로드
   - 배포 브랜치에는 `dev`의 내용만 쌓이므로 항상 그대로 합쳐집니다(충돌 없음).
4. 배포 브랜치에서 급하게 고칠 일이 생겨도 **`dev`에 먼저 고치고** 다시 배포 PR을 올립니다.

## 언제 어느 브랜치로 PR을 올리나

| 하고 싶은 것                                  | PR                            |
| --------------------------------------------- | ----------------------------- |
| 기능 개발, 버그 수정, iOS·토스 전용 코드 수정 | `feat/…` 또는 `fix/…` → `dev` |
| 웹에 반영                                     | `dev`에 머지되면 자동         |
| iOS 앱 새 빌드 (TestFlight)                   | `dev` → `ios`                 |
| 앱인토스 배포                                 | `dev` → `toss`                |
